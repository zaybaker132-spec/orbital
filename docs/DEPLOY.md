# Put Orbital online

Orbital as a website anyone can use from a browser: Mac, Windows, phones. You need three accounts:
**Supabase** (the database), **Render** (runs Orbital) and a **domain** (your web address). Plan on about an hour.

Orbital starts **invite-only**: visitors join the waitlist, and you let people in from Settings → Waitlist.

## 1. Database (Supabase)

1. In your Supabase project, open **Database → Extensions**, search **vector**, and turn it on.
2. Click **Connect** (top of the project page) → **Connection string** → choose **Session pooler**
   (works with Render; the "Direct connection" needs IPv6). Copy it. It looks like
   `postgresql://postgres.<project-ref>:[YOUR-PASSWORD]@aws-0-<region>.pooler.supabase.com:5432/postgres`
3. Replace `[YOUR-PASSWORD]` with your database password. Don't remember it? **Database → Settings → Reset database
   password**. Keep this full string private. You'll paste it into Render only, never into chat or code.

Orbital talks to Postgres directly. It doesn't use Supabase's API keys (publishable/secret), and on startup it closes its
tables to Supabase's public data API, so those keys can't read Orbital's data.

Optional, stricter: **Database → Settings → SSL → Download certificate**, and paste its contents into a Render
setting called `DATABASE_SSL_CA`. The connection is always encrypted; with the certificate, Orbital also verifies it's
talking to Supabase.

## 2. Orbital (Render)

1. Sign in at render.com with GitHub. **New → Blueprint** → pick the `orbital` repository. Render reads `render.yaml`.
2. It asks for these settings:
   - `DATABASE_URL`: the connection string from step 1
   - `ANTHROPIC_API_KEY`: a key from console.anthropic.com (make a new one just for the website)
   - `ORBITAL_PUBLIC_URL`: your site's address, e.g. `https://orbital.yourdomain.com` (until the domain is set up,
     use the `https://orbital-xxxx.onrender.com` address Render shows, and change it later)
   - `ORBITAL_ADMIN_EMAILS`: your email address
3. Click **Apply**. The first build takes a few minutes. When it says **Live**, open the address.
4. Click **Create an account** with your admin email. You're in.

`ORBITAL_SECRET_KEY` is generated by Render automatically. Never change or delete it: it decrypts saved webhook
addresses and tokens.

## 3. Your domain

1. Buy a domain (Cloudflare, Namecheap…).
2. In Render: your service → **Settings → Custom Domains → Add** → type e.g. `orbital.yourdomain.com`.
3. Render shows a DNS record (usually a CNAME). Add it at your domain provider. Within minutes to a few hours the site
   works at your address with HTTPS.
4. Update `ORBITAL_PUBLIC_URL` in Render to the new address.

## 4. Let people in

- Share `https://your-address/waitlist`.
- **Settings → Waitlist** (only for admin emails) lists sign-ups, with **Let in** on each. Someone you let in goes to the
  sign-in page, clicks **Create an account** and uses the email they joined with.
- To open sign-up to everyone: set `ORBITAL_ALLOW_SIGNUP` to `true` in Render.

## 5. Before you announce it

- **AI cost:** everyone's questions use your Anthropic key. Set a monthly spending limit at console.anthropic.com, and let
  people in gradually.
- **Privacy policy and terms:** you're storing people's personal data. Add both before opening to the public.
- **Backups:** Supabase backs up daily on paid plans; on the free plan, export regularly (Settings → Your data →
  Export, per workspace) or upgrade.
- **Meetings on strict networks** need a TURN relay (see `docs/MEETINGS.md`). Optional.

## Updating

Every push to `main` on GitHub redeploys automatically (`autoDeploy` in `render.yaml`). Database changes apply
themselves on startup.
